## 2. Proposed Solution: Anti-False-Positive Gates (AFP Gates)

### 2.1 Gate Architecture

```yaml
anti_false_positive_gates:
  description: |
    Mandatory verification gates that MUST pass before any finding
    can be reported as HIGH or CRITICAL severity.

  enforcement: HARD  # Cannot be bypassed without human override

  applies_to:
    - severity: [HIGH, CRITICAL]
    - precision_level: [PL3, PL4, PL5]
    - template: [TMPL-SEC, TMPL-SEC-AUTO]

  gates:
    - id: AFP-GATE-1
      name: "Changelog Verification Gate"

    - id: AFP-GATE-2
      name: "Default Configuration Gate"

    - id: AFP-GATE-3
      name: "Source Code Verification Gate"

    - id: AFP-GATE-4
      name: "Working PoC Gate"

    - id: AFP-GATE-5
      name: "Bug Bounty Eligibility Gate"
```

### 2.2 Gate Specifications

#### AFP-GATE-1: Changelog Verification Gate

```yaml
gate_1_changelog:
  id: AFP-GATE-1
  name: "Changelog Verification Gate"

  purpose: |
    Verify the vulnerability has NOT already been fixed by checking
    changelogs, NEWS files, commit history, and CVE databases.

  trigger: "Before reporting any vulnerability"

  required_checks:
    - check_1:
        name: "Search NEWS/CHANGELOG"
        action: |
          grep -i "{vulnerability_pattern}" NEWS CHANGELOG CHANGES History.md
          grep -i "{function_name}" NEWS CHANGELOG CHANGES
        pass_if: "No mention of fix for this specific issue"

    - check_2:
        name: "Search Git History"
        action: |
          git log --oneline --all --grep="{function_name}" | head -20
          git log --oneline --all --grep="fix.*{vulnerability_type}"
        pass_if: "No commits fixing this issue"

    - check_3:
        name: "Check CVE Database"
        action: |
          Search NVD, MITRE for existing CVEs matching this pattern
        pass_if: "Not already assigned a CVE that was fixed"

  on_failure:
    action: "BLOCK finding, mark as POTENTIAL DUPLICATE"
    error_code: "AFP-3001"
    human_review: "Required before proceeding"

  example_that_would_have_caught:
    - "USF-VARIANT-001: NEWS line 2449 shows 'Fix buffer size checks in xmlSnprintfElementContent'"
```

#### AFP-GATE-2: Default Configuration Gate

```yaml
gate_2_default_config:
  id: AFP-GATE-2
  name: "Default Configuration Gate"

  purpose: |
    Verify the vulnerability exists in DEFAULT configurations,
    not just when users explicitly enable dangerous features.

  trigger: "Before reporting XXE, SSRF, injection vulnerabilities"

  required_checks:
    - check_1:
        name: "Test Default Parser Settings"
        action: |
          # Test with NO special flags/options
          {tool} {input_file}  # NOT: {tool} --dangerous-flag {input_file}
        pass_if: "Vulnerability triggered with default settings"

    - check_2:
        name: "Document Required Opt-In"
        action: |
          List any flags, options, or API calls required to trigger
        fail_if: |
          User must explicitly enable feature via:
          - Command-line flags (--noent, --resolve-entities)
          - API options (resolve_entities=True, XML_PARSE_NOENT)
          - Configuration files with non-default values

    - check_3:
        name: "Check Documentation"
        action: |
          Verify if the behavior is DOCUMENTED as dangerous
        fail_if: "Documentation explicitly warns users about this behavior"

  on_failure:
    action: "DOWNGRADE to INFORMATIONAL or reject"
    error_code: "AFP-3002"
    classification: "Documented Feature, Not Vulnerability"

  example_that_would_have_caught:
    - "USF-XXE-001-004: XXE requires --noent flag or resolve_entities=True"
    - "Default lxml: ERROR 'Entity xxe not defined' - SAFE"
```

#### AFP-GATE-3: Source Code Verification Gate

```yaml
gate_3_source_verification:
  id: AFP-GATE-3
  name: "Source Code Verification Gate"

  purpose: |
    Verify claimed vulnerability by reading ACTUAL source code,
    not just pattern matching or assuming based on function names.

  trigger: "Before reporting memory safety, buffer overflow, integer overflow"

  required_checks:
    - check_1:
        name: "Read Actual Function"
        action: |
          Read complete function source, not just signature
          Document exact lines where vulnerability exists
        pass_if: "Vulnerability visible in actual code"

    - check_2:
        name: "Check Existing Protections"
        action: |
          Look for existing:
          - Bounds checks (if (size - len < N))
          - Input validation
          - Safe string functions (snprintf vs sprintf)
          - Return-on-error patterns
        fail_if: "Adequate protection already exists"

    - check_3:
        name: "Trace Data Flow"
        action: |
          Trace attacker-controlled input to vulnerable sink
          Document complete path
        pass_if: "Clear data flow from input to vulnerability"

  on_failure:
    action: "BLOCK finding, mark as UNVERIFIED"
    error_code: "AFP-3003"

  example_that_would_have_caught:
    - "USF-VARIANT-001: valid.c:977-982 already has 'if (size - len < 50)' check"
```

#### AFP-GATE-4: Working PoC Gate

```yaml
gate_4_working_poc:
  id: AFP-GATE-4
  name: "Working PoC Gate"

  purpose: |
    Require a WORKING proof-of-concept that demonstrates
    actual exploitation, not just theoretical claims.

  trigger: "Before reporting HIGH/CRITICAL severity findings"

  required_criteria:
    poc_requirements:
      - "PoC must be self-contained (no external dependencies)"
      - "PoC must work on unmodified target software"
      - "PoC must demonstrate claimed impact"
      - "PoC must be reproducible (document exact steps)"
      - "PoC must NOT require victim to enable dangerous options"

    execution_evidence:
      - "Screenshot or log output showing exploitation"
      - "Exact commands used to trigger"
      - "Environment details (OS, version, config)"

    what_does_not_count:
      - "Theoretical analysis without execution"
      - "Code pattern that 'looks vulnerable'"
      - "PoC that requires --enable-dangerous-mode"
      - "PoC that requires older, unpatched version"

  verification_method: |
    MUST actually run the PoC and observe:
    - Crash (for memory corruption)
    - File read (for XXE/LFI)
    - Network callback (for SSRF/OOB)
    - Arbitrary code execution (for RCE)

  on_failure:
    action: "DOWNGRADE to MEDIUM or UNVERIFIED"
    error_code: "AFP-3004"

  example_that_would_have_caught:
    - "USF-MEM-001: No working PoC demonstrating memory exhaustion"
    - "CVE-2024-40896 bypass: No PoC bypassing with default config"
```

#### AFP-GATE-5: Bug Bounty Eligibility Gate

```yaml
gate_5_bounty_eligibility:
  id: AFP-GATE-5
  name: "Bug Bounty Eligibility Gate"

  purpose: |
    Final gate to verify finding is actually eligible for
    bug bounty submission before generating reports.

  trigger: "Before generating bug bounty submission reports"

  checklist:
    eligibility_criteria:
      - question: "Is this a NEW vulnerability (not duplicate)?"
        verify_with: "AFP-GATE-1"

      - question: "Does it affect DEFAULT configuration?"
        verify_with: "AFP-GATE-2"

      - question: "Is the vulnerability verified in source?"
        verify_with: "AFP-GATE-3"

      - question: "Do you have a WORKING PoC?"
        verify_with: "AFP-GATE-4"

      - question: "Is the target in scope for the program?"
        verify_with: "Check program scope document"

      - question: "Is this actual security impact, not just 'bad practice'?"
        criteria: |
          Must have ONE of:
          - Arbitrary code execution
          - Arbitrary file read/write
          - Authentication bypass
          - Privilege escalation
          - Sensitive data exposure
          NOT:
          - Self-DoS (user DoSes themselves)
          - Requires victim to enable dangerous feature
          - Theoretical without demonstrated impact

    disqualifiers:
      - "Vulnerability requires non-default configuration"
      - "Already fixed in current version"
      - "Documented behavior, not a bug"
      - "Requires physical access"
      - "Requires authenticated admin access"
      - "Social engineering required"

  on_failure:
    action: "DO NOT SUBMIT - document why"
    error_code: "AFP-3005"
    generate: "Internal learning document, NOT bounty report"

  example_that_would_have_caught:
    - "ALL 7 libxml2 findings would have failed this gate"
```

## 7. Appendix: libxml2 Lessons Learned

### What We Did Wrong

1. **Assumed pattern = vulnerability**
   - Found similar code pattern to CVE-2025-24928
   - Did NOT read the actual function
   - Missed that it was already fixed

2. **Didn't check changelogs**
   - NEWS file line 2449 explicitly said "Fix buffer size checks in xmlSnprintfElementContent"
   - We never searched the NEWS file for this function

3. **Confused features with bugs**
   - XXE is a documented feature
   - Requires user to explicitly enable with --noent or resolve_entities=True
   - Default configuration is SAFE

4. **Made claims without PoCs**
   - "CVE-2024-40896 bypass" - no working PoC
   - "Memory corruption" - no working PoC
   - Speculation presented as fact

### What We Should Have Done

1. **Search NEWS/CHANGELOG FIRST**
   ```bash
   grep -i "xmlSnprintfElementContent" NEWS
   # Would have found: "Fix buffer size checks in xmlSnprintfElementContent"
   ```

2. **Test default configuration FIRST**
   ```python
   parser = etree.XMLParser()  # DEFAULT
   etree.parse("xxe.xml", parser)
   # Error: Entity 'xxe' not defined - SAFE
   ```

3. **Read actual source code**
   ```c
   // valid.c:977-982 - ALREADY HAS PROTECTION
   if (size - len < 50) {
       if ((size - len > 4) && (buf[len - 1] != '.'))
           strcat(buf, " ...");
       return;  // Safe return
   }
   ```

4. **Create working PoC before claiming**
   - No PoC = No claim
   - Speculation ≠ Vulnerability
